## 已验证的存储与传输接口

- `S3Config` 是部署配置，包含 bucket、prefix、endpoint、region、寻址方式及可选凭据。省略凭据时使用 SDK 凭据链；显式临时会话令牌需完整凭据。凭据用 `SecretStr` 隐藏，`Settings` 导出与备份不包含 S3 配置。
- `ObjectStore` 的同步网络接口只允许在线程或独立工作进程调用。对象键为服务器分配的随机标识，所有操作约束在同一配置前缀内。
- 上传先计算完整 SHA256，再按有界分片传输并发送每片 MD5。完成前再次检查源文件身份及大小；`IfNoneMatch: *` 阻止覆盖已有对象。记录 ETag、版本号、SHA256、大小、修改时间及传输所有权标识。
- 读取固定版本及 ETag，检查返回的身份和长度；下载重新验证完整 SHA256，成功后原子替换本地目标。删除使用原版本及 `IfMatch`，避免删除外部更新后的对象。
- `upload_original` / `download_original` 使用现有进程组控制和进度协议；暂停实际工作进程，取消会终止并回收子进程。上传取消清理 multipart 与本次传输已发布的对象，下载取消保留原本已验证的本地文件。
- 请求凭据通过 0700 私有目录内的 0600 文件传递，命令行只包含文件路径。清理失败保留不含凭据的恢复记录；`recover_transfers` 严格匹配 bucket、prefix、endpoint，不访问其他命名空间。调用方需持有库锁并在工作进程启动前恢复。

真实协议测试使用由官方固定源码 `9e49d5e7a648` 构建的独立 MinIO，临时 bucket 按测试唯一分配并清理。验证包含真实 MP4／FFprobe、分片上传、版本、条件覆盖拒绝、Range、工作进程进度、远端分片暂停／恢复／取消、部分下载取消、发布后取消、校验损坏与恢复清理。

## 协议专项复现

构建测试服务的 Dockerfile 位于 `backend/tests/s3/Dockerfile`。服务只监听本机，使用测试专用凭据与新建测试 bucket；不要将生产 bucket 用作测试。

```sh
uv sync --project backend --extra s3
# 启动自己的本机 MinIO 测试服务后设置：
export REELVAULT_TEST_S3_ENDPOINT=http://127.0.0.1:9000
export REELVAULT_TEST_S3_ACCESS_KEY='<test-access-key>'
export REELVAULT_TEST_S3_SECRET_KEY='<test-secret-key>'
cd backend
uv run --frozen --extra s3 pytest -q tests/test_object_store.py tests/test_object_transfer.py
```

未提供测试 endpoint 时真实服务测试跳过；CI 的独立 `S3 (MinIO)` 作业会构建服务并提供配置，因此不会跳过这些验证。
